Fundamentos

Privacidad de los datos

Los datos de una persona no son un recurso ilimitado: solo deben recolectarse los estrictamente necesarios para el propósito declarado (minimización de datos) y con consentimiento informado. En DataLab todos los datasets son sintéticos y reproducibles precisamente para no exponer información real durante las demostraciones.

Protección de la información

Proteger información implica tres pilares: confidencialidad (solo acceso autorizado), integridad (los datos no se alteran sin control) y disponibilidad (accesibles cuando se necesitan). Este proyecto ejecuta todo localmente sin servicios externos, lo que reduce la superficie de exposición durante la demostración.

Uso responsable de algoritmos

Un algoritmo solo decide con el criterio que su autor le dio. El mismo greedy puede asignar turnos de manera eficiente o incentivar comportamientos injustos si el criterio de "optimidad" está mal definido. La responsabilidad técnica incluye documentar qué optimiza el algoritmo y qué sacrifica.

Sesgos algorítmicos

Un sesgo ocurre cuando el algoritmo amplifica desigualdades presentes en los datos o en el diseño. Fuentes típicas:

  • Sesgo de datos: el conjunto de entrenamiento no representa a toda la población.
  • Sesgo de selección: la métrica de optimización favorece a un grupo (p. ej. "seleccionar por horas de experiencia" excluye a quien trabajó a medio tiempo).
  • Sesgo de retroalimentación: la salida del algoritmo influye en los datos futuros que recibe.

Escenario para el debate

Un banco usa un modelo de scoring entrenado con su historial de préstamos. Históricamente, cierto distrito recibió menos préstamos, por lo que el modelo le asigna menor puntaje y el ciclo se retroalimenta. ¿Es el modelo el problema o los datos que lo alimentaron? ¿Quién debe auditar el resultado?

Escenario: greedy con criterio questionable

El algoritmo greedy de selección de actividades de este laboratorio siempre elige la que termina primero. Es óptimo para "máximo número de actividades", pero si el objetivo real fuera "máximo valor total por actividad" la estrategia voraz dejaría de ser óptima. Elegir el algoritmo es también elegir qué valoramos.

Seguridad durante el procesamiento
  • Validación de entradas: toda la API de DataLab valida tipos, rangos y límites antes de ejecutar (ver routes/); las solicitudes inválidas devuelven 400 con un mensaje claro.
  • Límites de recursos: las operaciones costosas tienen topes explícitos (n máximo, límite de recursión en Fibonacci, tamaños omitidos en benchmarks) para no bloquear el servidor.
  • Manejo de excepciones: los errores se capturan y se devuelven como JSON consistente, nunca se filtran trazas internas al cliente.

Transparencia

La transparencia exige poder explicar qué hace el algoritmo, con qué datos y por qué produce ese resultado. DataLab lo practica: cada laboratorio muestra el análisis Big O, los contadores de operaciones y el porqué de cada decisión (por ejemplo, las decisiones comentadas del módulo greedy). Ningún resultado está precalculado ni simulado.

Principio guía del proyecto: mostrar el funcionamiento real con mediciones reales es la forma más honesta de enseñar y de auditar un sistema. Si un componente no se puede explicar, no se puede confiar en él.
